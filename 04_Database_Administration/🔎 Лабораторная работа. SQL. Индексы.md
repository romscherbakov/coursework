### 🔬 Как определить селективность атрибута

При выборе порядка атрибутов в составном индексе необходимо учитывать количество уникальных значений.

Например, чтобы сравнить селективность атрибутов `series` и `number`, выполните:

```sql
SELECT
    COUNT(*) AS total_rows,
    COUNT(DISTINCT series) AS unique_series,
    COUNT(DISTINCT number) AS unique_number,
    ROUND(COUNT(DISTINCT series) / COUNT(*) * 100, 2)
        AS series_selectivity,
    ROUND(COUNT(DISTINCT number) / COUNT(*) * 100, 2)
        AS number_selectivity
FROM workers;
```

**На что обратить внимание:**

- `total_rows` — общее количество записей.
- `unique_series` — количество уникальных серий.
- `unique_number` — количество уникальных номеров.
- `series_selectivity` — доля уникальных серий относительно общего количества записей.
- `number_selectivity` — доля уникальных номеров относительно общего количества записей.

Чем больше уникальных значений относительно общего количества записей, тем выше потенциальная селективность атрибута при поиске по равенству.

Полученные результаты необходимо использовать для обоснования порядка атрибутов в составном индексе.

**Важно:** количество уникальных значений — это ориентир, а не универсальное правило выбора порядка атрибутов. Также необходимо учитывать условия `WHERE`, диапазоны поиска, сортировку и характер использования индекса в других запросах.

**При проектировании индекса нужно учитывать одновременно:**
1. Селективность полей.
2. Условия поиска (=, IN, BETWEEN).
3. Наличие диапазонов.
4. Сортировку (ORDER BY).

<summary>📊 Справка по EXPLAIN</summary>

Для изучения плана выполнения запроса используйте:

```sql
EXPLAIN
SELECT *
FROM workers
WHERE first_name = 'Иван';
```

### Ключевые показатели EXPLAIN

**type** — тип доступа к данным.

| Тип | Описание |
|---|---|
| `const` | Поиск по уникальному индексу, результат — не более одной строки |
| `eq_ref` | Поиск одной строки по уникальному индексу при соединении таблиц |
| `ref` | Поиск по неуникальному индексу |
| `range` | Поиск по диапазону индекса |
| `index` | Полное сканирование индекса |
| `ALL` | Полное сканирование таблицы |

`ALL` не всегда означает плохой запрос. Иногда полное сканирование таблицы оказывается эффективнее использования индекса.

**key** — индекс, который выбрал MySQL для выполнения запроса.

**rows** — оценочное количество строк, которые MySQL предполагает проверить.

**Extra** — дополнительная информация о выполнении запроса.

| Значение | Описание |
|---|---|
| `Using where` | Дополнительная фильтрация строк |
| `Using index` | Запрос обслуживается непосредственно из индекса |
| `Using filesort` | Выполняется дополнительная операция сортировки |
| `Using temporary` | Используется внутренняя временная таблица |

### На что обращать внимание

- Используется ли индекс (`key`)?
- Какой тип доступа (`type`) выбран?
- Сколько строк предполагается проверить (`rows`)?
- Требуется ли дополнительная сортировка (`Using filesort`)?
- Используется ли временная таблица (`Using temporary`)?

**Важно:** не нужно стремиться любой ценой избавиться от `ALL`, `Using filesort` или `Using temporary`. Необходимо оценивать весь план выполнения и понимать, насколько эффективно СУБД выполняет конкретный запрос.

<details>
<summary>📈 Справка по EXPLAIN ANALYZE</summary>

`EXPLAIN ANALYZE` не просто показывает предполагаемый план выполнения, а фактически выполняет запрос и собирает информацию о работе операций.

Используйте команду:

```sql
EXPLAIN ANALYZE
SELECT *
FROM workers
WHERE first_name = 'Иван';
```

В отличие от обычного `EXPLAIN`, результат `EXPLAIN ANALYZE` представлен в виде дерева операций.

### На что обращать внимание

| Показатель | Описание |
|---|---|
| `cost` | Расчётная стоимость операции, которую оценивает оптимизатор MySQL |
| `actual time` | Фактическое время выполнения операции в миллисекундах |
| `rows` | Фактическое количество строк, полученных операцией |
| `loops` | Количество повторений операции |

**Важно различать:**

- `cost` — не время выполнения в миллисекундах и не процент загрузки процессора. Это внутренняя оценка затрат оптимизатора.
- `actual time` — фактически измеренное время выполнения операции.
- `rows` — фактическое количество строк, возвращённых операцией.
- `loops` — сколько раз выполнялась операция.

При сравнении запросов обращайте внимание не только на `actual time`, но и на количество обработанных строк, число повторений операций и выбранный способ доступа к данным.

**Важно:** фактическое время может меняться в зависимости от состояния кэша, нагрузки на сервер и других факторов. Поэтому не делайте вывод об эффективности индекса только по одному измерению.

<summary>🛠️ Шпаргалка по работе с индексами</summary>

### Просмотр индексов таблицы

```sql
SHOW INDEX FROM workers;

-- Или
SHOW KEYS FROM workers;
```

### Создание индексов

```sql
-- Простой индекс
CREATE INDEX idx_column
ON table_name(column_name);

-- Уникальный индекс
CREATE UNIQUE INDEX idx_unique_column
ON table_name(column_name);

-- Составной индекс
CREATE INDEX idx_multiple
ON table_name(col1, col2, col3);
```

### Удаление индексов

```sql
DROP INDEX index_name ON workers;
```

### Проверка использования индекса

```sql
EXPLAIN
SELECT *
FROM workers
WHERE first_name = 'Иван';
```

### Фактический анализ выполнения запроса

```sql
EXPLAIN ANALYZE
SELECT *
FROM workers
WHERE first_name = 'Иван';
```

### Обновление статистики таблицы

```sql
ANALYZE TABLE workers;
```

Команда обновляет статистику, которую оптимизатор MySQL использует при выборе плана выполнения запроса.

<details>
<summary>⚠️ Важные замечания</summary>

1. Индексы ускоряют поиск и чтение данных, но требуют дополнительного места на диске.
2. При добавлении, удалении и обновлении записей индексы также необходимо изменять, поэтому они могут замедлять операции записи.
3. Составной индекс учитывает порядок атрибутов. Для обычного поиска по его левому префиксу порядок полей имеет значение.
4. Большое количество индексов не гарантирует высокую производительность.
5. Индекс может использоваться для фильтрации, но при этом MySQL всё равно может выполнять дополнительную сортировку.

**Главная задача лабораторной работы:** научиться анализировать запросы, самостоятельно выбирать подходящие индексы, обосновывать порядок атрибутов в составных индексах и оценивать результат оптимизации с помощью `EXPLAIN` и `EXPLAIN ANALYZE`.
