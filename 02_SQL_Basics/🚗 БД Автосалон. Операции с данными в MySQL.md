# Практическая работа: Операции с данными в MySQL

## База данных «Автосалон»

**Цель работы:** научиться добавлять, удалять и изменять данные, проверять работу `AUTO_INCREMENT` и исследовать механизмы ссылочной целостности.

В работе используются таблицы:

- `model` — модели автомобилей;
- `config` — комплектации;
- `car` — автомобили;
- `client` — клиенты;
- `employee` — сотрудники;
- `booking` — бронирования;
- `sale` — продажи.

Все SQL-команды выполняйте в базе данных `autosalon`.

```sql
USE autosalon;
```

**Важно:** перед выполнением заданий изучите структуру таблиц и действующие ограничения внешних ключей. Примеры ниже предназначены для проверки на учебных данных. При необходимости замените значения идентификаторов на существующие в вашей базе.

## Часть 1. Добавление данных (`INSERT`)

### Задание 1. Добавление записей

Добавьте по две новые записи в таблицы `model`, `config`, `car`, `client`, `employee`, `booking` и `sale`.

**Требования:**

1. Не указывайте значения первичных ключей (`model_id`, `config_id`, `car_id` и т. д.) — они должны генерироваться автоматически.
2. Для внешних ключей используйте идентификаторы существующих записей либо записей, созданных в предыдущих шагах.
3. Соблюдайте ограничения `NOT NULL`, `UNIQUE`, `FOREIGN KEY` и допустимые значения `ENUM`.
4. Для продаж и бронирований используйте разные автомобили, чтобы один автомобиль не участвовал одновременно в новой продаже и новом бронировании.

### Примеры SQL-команд

**1. Добавление моделей автомобилей**

```sql
INSERT INTO model (brand, name, release_year)
VALUES
    ('Toyota', 'RAV4', 2025),
    ('Kia', 'Sportage', 2025);
```

**2. Добавление комплектаций**

В примере используются существующие модели с `model_id = 1` и `model_id = 2`.

```sql
INSERT INTO config
    (name, config_price, description, model_id)
VALUES
    ('Comfort учебная', 25000.00, 'Базовая комплектация', 1),
    ('Premium учебная', 35000.00, 'Расширенная комплектация', 2);
```

Если такие названия уже заняты ограничением `UNIQUE`, выберите другие.

**3. Добавление автомобилей**

В примере используются комплектации с `config_id = 1` и `config_id = 2`.

```sql
INSERT INTO car
    (vin, color, production_year, config_id)
VALUES
    ('TESTVIN0000000001', 'Белый', 2025, 1),
    ('TESTVIN0000000002', 'Серый', 2025, 2);
```

VIN в примере — учебные значения. Если они уже существуют, замените их уникальными значениями.

**4. Добавление клиентов**

```sql
INSERT INTO client (first_name, last_name, phone, email)
VALUES
    ('Иван', 'Петров', '+37120000001', 'student1@example.com'),
    ('Анна', 'Соколова', '+37120000002', 'student2@example.com');
```

**5. Добавление сотрудников**

```sql
INSERT INTO employee (first_name, last_name, position, phone, email)
VALUES
    ('Олег', 'Иванов', 'Менеджер', '+37120000003', 'employee1@example.com'),
    ('Мария', 'Калныня', 'Консультант', '+37120000004', 'employee2@example.com');
```

**6. Добавление бронирований**

Для примера используются существующие записи автомобиля, клиента и сотрудника. Перед выполнением убедитесь, что выбранный автомобиль не участвует в продаже и не имеет конфликтующего бронирования.

```sql
INSERT INTO booking
    (car_id, client_id, booking_status,
     booking_date, expiry_date, employee_id)
VALUES
    (12, 1, 'active', '2026-11-01 10:00:00',
     '2026-11-05 10:00:00', 1);
```

**7. Добавление продажи**

Используйте другой автомобиль, который не участвует в новом бронировании и ещё не имеет записи в `sale`.

```sql
INSERT INTO sale
    (sale_price, sale_date, car_id, client_id,
     employee_id, payment_method, sale_status)
VALUES
    (28000.00, '2026-11-02 12:00:00', 2, 2,
     1, 'cash', 'in_processing');
```

Это примеры отдельных операций, а не готовый скрипт для последовательного выполнения без проверки данных. Для добавления двух продаж и двух бронирований понадобятся четыре разных автомобиля, не занятых существующими продажами и бронированиями. Если свободных автомобилей недостаточно, сначала добавьте необходимое количество автомобилей.

### Проверка результата

```sql
SELECT * FROM model ORDER BY model_id DESC LIMIT 5;
SELECT * FROM config ORDER BY config_id DESC LIMIT 5;
SELECT * FROM car ORDER BY car_id DESC LIMIT 5;
SELECT * FROM client ORDER BY client_id DESC LIMIT 5;
SELECT * FROM employee ORDER BY employee_id DESC LIMIT 5;
SELECT * FROM booking ORDER BY booking_id DESC LIMIT 5;
SELECT * FROM sale ORDER BY sale_id DESC LIMIT 5;
```

Зафиксируйте:
- какие значения первичных ключей были присвоены автоматически;
- соответствуют ли они ожидаемым значениям;
- появились ли новые записи;
- какие ошибки возникли и чем они вызваны.

## Часть 2. Удаление данных (`DELETE`)

### Задание 2. Проверка ссылочной целостности

Выполните следующие действия и проанализируйте результат.

1. Попробуйте удалить модель, на которую ссылается хотя бы одна комплектация.
2. Попробуйте удалить комплектацию, которая используется автомобилями.
3. Попробуйте удалить автомобиль, связанный с продажей или бронированием.
4. Попробуйте удалить клиента, у которого есть записи в `booking` или `sale`.
5. Попробуйте удалить сотрудника, связанного с бронированием или продажей.
6. Удалите одну запись, на которую не ссылаются другие таблицы.

### Примеры SQL-команд

**1. Попытка удалить модель, используемую комплектациями**

```sql
DELETE FROM model
WHERE model_id = 1;
```

Если на модель ссылаются записи в `config`, операция может быть запрещена правилом `ON DELETE RESTRICT` или `ON DELETE NO ACTION`.

**2. Попытка удалить комплектацию, используемую автомобилями**

```sql
DELETE FROM config
WHERE config_id = 1;
```

**3. Попытка удалить автомобиль, связанный с продажей или бронированием**

```sql
DELETE FROM car
WHERE car_id = 1;
```

**4. Попытка удалить клиента, имеющего связанные записи**

```sql
DELETE FROM client
WHERE client_id = 1;
```

**5. Попытка удалить сотрудника, связанного с бронированием или продажей**

```sql
DELETE FROM employee
WHERE employee_id = 1;
```

Для этих проверок заранее убедитесь, что выбранные записи действительно имеют зависимые записи в дочерних таблицах.

**6. Удаление независимой записи**

Например, можно удалить специально созданную модель, если к ней ещё не добавлены комплектации:

```sql
DELETE FROM model
WHERE brand = 'TestBrand'
  AND name = 'TestModel';
```

Предварительно добавьте такую модель и убедитесь, что она не используется другими таблицами.

**Внимание:** запрос `DELETE` без `WHERE` удалит все записи таблицы. Всегда проверяйте условие перед выполнением.

Для каждого действия зафиксируйте:
- выполнилась ли операция;
- если возникла ошибка, почему;
- какое ограничение ссылочной целостности сработало.

**Вопрос:** почему MySQL запрещает удалять некоторые записи, даже если пользователь имеет право выполнять `DELETE`?

## Часть 3. Изменение данных (`UPDATE`)

### Задание 3. Проверка ссылочной целостности

1. Измените название одной модели в таблице `model`.
2. Измените цену одной комплектации в таблице `config`.
3. Измените контактные данные одного клиента в таблице `client`.
4. Попробуйте изменить первичный ключ модели, на которую ссылаются комплектации.
5. Попробуйте изменить первичный ключ комплектации, на которую ссылаются автомобили.
6. Попробуйте изменить первичный ключ автомобиля, связанного с продажей или бронированием.
7. Попробуйте указать для внешнего ключа несуществующий идентификатор родительской записи.

### Примеры SQL-команд

**1. Изменение названия модели**

```sql
UPDATE model
SET name = 'Corolla обновлённая'
WHERE model_id = 1;
```

**2. Изменение цены комплектации**

```sql
UPDATE config
SET config_price = 32000.00
WHERE config_id = 1;
```

**3. Изменение контактных данных клиента**

```sql
UPDATE client
SET phone = '+37120000111',
    email = 'updated_client@example.com'
WHERE client_id = 1;
```

**4. Попытка изменить первичный ключ модели**

```sql
UPDATE model
SET model_id = 100
WHERE model_id = 1;
```

Если комплектации ссылаются на эту модель, результат зависит от правила внешнего ключа `ON UPDATE`. При `RESTRICT` или `NO ACTION` операция будет отклонена; при `CASCADE` связанные внешние ключи могут обновиться автоматически.

**5. Попытка изменить первичный ключ комплектации**

```sql
UPDATE config
SET config_id = 100
WHERE config_id = 1;
```

Проверьте правило `ON UPDATE` ограничения, связывающего `config` и `car`.

**6. Попытка изменить первичный ключ автомобиля**

```sql
UPDATE car
SET car_id = 100
WHERE car_id = 1;
```

Если на автомобиль ссылаются продажи или бронирования, результат зависит от настроенных правил `ON UPDATE` соответствующих внешних ключей.

Для проверки каскадного обновления используйте тестовые записи и сначала выясните действующие правила ограничений. В рабочей базе первичные ключи обычно не изменяют.

**7. Попытка указать несуществующий внешний ключ**

```sql
UPDATE car
SET config_id = 999999
WHERE car_id = 12;
```

Если комплектации с таким `config_id` нет, MySQL отклонит операцию из-за нарушения ограничения внешнего ключа.

После каждого действия проверьте изменения в связанных таблицах.

Зафиксируйте:
- какие операции выполнились успешно;
- какие операции были отклонены;
- в каких случаях сработал `ON UPDATE CASCADE`;
- почему нельзя указать несуществующий идентификатор внешнего ключа.
