# Практическая работа: Операции с данными в MySQL

## База данных «Автосалон»

**Цель работы:** научиться добавлять, удалять и изменять данные, проверять работу `AUTO_INCREMENT` и исследовать механизмы ссылочной целостности.

В работе используются таблицы:

- `model` — модели автомобилей;
- `config` — комплектации;
- `car` — автомобили;
- `client` — клиенты;
- `employee` — сотрудники;
- `booking` — бронирования;
- `sale` — продажи.

Все SQL-команды выполняйте в базе данных `autosalon`.

```sql
USE autosalon;
```

**Важно:** перед выполнением заданий изучите структуру таблиц и действующие ограничения внешних ключей. Команды, которые могут изменить или удалить существующие данные, сначала проверяйте на учебных записях.

## Часть 1. Добавление данных (`INSERT`)

### Задание 1. Добавление записей

Добавьте новые записи в таблицы `model`, `config`, `car`, `client`, `employee`, `booking` и `sale`.

Для проверки работы `AUTO_INCREMENT` необходимо добавить три автомобиля:

- **Автомобиль № 1** — продан, имеет запись в `sale`.
- **Автомобиль № 2** — забронирован, имеет запись в `booking`.
- **Автомобиль № 3** — свободен, не имеет записей в `sale` и `booking`.

**Требования:**

1. Не указывайте значения первичных ключей (`model_id`, `config_id`, `car_id` и т. д.) — они должны генерироваться автоматически.
2. Для внешних ключей используйте идентификаторы существующих записей либо записей, созданных на предыдущих шагах.
3. Соблюдайте ограничения `NOT NULL`, `UNIQUE`, `FOREIGN KEY` и допустимые значения `ENUM`.
4. Используйте разные автомобили для продажи и бронирования.
5. Для получения именно `car_id = 1`, `2` и `3` таблица `car` должна быть пустой, а счётчик `AUTO_INCREMENT` — начинаться с 1. Если таблица уже содержит данные, фактические идентификаторы могут отличаться.

### 1.1. Добавление моделей автомобилей

## Часть 2. Удаление данных (`DELETE`)

### Задание 2. Проверка ссылочной целостности

Выполните следующие действия и проанализируйте результат.

1. Попробуйте удалить модель, на которую ссылается хотя бы одна комплектация.
2. Попробуйте удалить комплектацию, которая используется автомобилями.
3. Попробуйте удалить автомобиль № 1, связанный с продажей.
4. Попробуйте удалить автомобиль № 2, связанный с бронированием.
5. Попробуйте удалить клиента, у которого есть записи в `booking` или `sale`.
6. Попробуйте удалить сотрудника, связанного с бронированием или продажей.
7. Удалите автомобиль № 3, если на него не ссылаются другие таблицы.

### Примеры SQL-команд

**1. Удаление модели, используемой комплектациями**

```sql
DELETE FROM model
WHERE model_id = 1;
```

Если на модель ссылаются комплектации, операция будет запрещена действующим правилом `ON DELETE RESTRICT` или `ON DELETE NO ACTION`.

**2. Удаление комплектации, используемой автомобилями**

```sql
DELETE FROM config
WHERE config_id = 1;
```

**3. Удаление проданного автомобиля**

```sql
DELETE FROM car
WHERE car_id = 1;
```

**4. Удаление забронированного автомобиля**

```sql
DELETE FROM car
WHERE car_id = 2;
```

Обе операции могут завершиться ошибкой, поскольку на автомобили ссылаются записи в `sale` или `booking`.

**5. Удаление клиента**

```sql
DELETE FROM client
WHERE client_id = 1;
```

**6. Удаление сотрудника**

```sql
DELETE FROM employee
WHERE employee_id = 1;
```

Если сотрудник используется в `booking` или `sale`, удаление может быть запрещено соответствующим внешним ключом.

**7. Удаление свободного автомобиля**

```sql
DELETE FROM car
WHERE car_id = 3;
```

Если на автомобиль не ссылаются другие таблицы, удаление должно пройти успешно.

Перед удалением проверьте зависимости:

```sql
SELECT *
FROM sale
WHERE car_id = 3;

SELECT *
FROM booking
WHERE car_id = 3;
```

**Важно:** выполняйте удаление автомобиля № 3 последним, если планируете использовать его в последующих заданиях. После успешного удаления он перестанет существовать в таблице `car`.

Для каждого действия зафиксируйте:

- выполнилась ли операция;
- если возникла ошибка, почему;
- какое ограничение ссылочной целостности сработало.

**Вопрос:** почему MySQL запрещает удалять некоторые записи, даже если пользователь имеет право выполнять `DELETE`?

## Часть 3. Изменение данных (`UPDATE`)

### Задание 3. Проверка ссылочной целостности

1. Измените название одной модели в таблице `model`.
2. Измените цену одной комплектации в таблице `config`.
3. Измените контактные данные одного клиента в таблице `client`.
4. Попробуйте изменить первичный ключ модели, на которую ссылаются комплектации.
5. Попробуйте изменить первичный ключ комплектации, на которую ссылаются автомобили.
6. Попробуйте изменить первичный ключ автомобиля № 1 или № 2, на который ссылаются продажи или бронирования.
7. Попробуйте указать для внешнего ключа несуществующий идентификатор родительской записи.

### Примеры SQL-команд

**1. Изменение названия модели**

```sql
UPDATE model
SET name = 'Camry обновлённая'
WHERE model_id = 1;
```

Проверка:

```sql
SELECT *
FROM model
WHERE model_id = 1;
```

**2. Изменение цены комплектации**

```sql
UPDATE config
SET config_price = 32000.00
WHERE config_id = 1;
```

Проверка:

```sql
SELECT *
FROM config
WHERE config_id = 1;
```

**3. Изменение контактных данных клиента**

```sql
UPDATE client
SET phone = '+37120000111',
    email = 'updated_client@example.com'
WHERE client_id = 1;
```

Проверка:

```sql
SELECT *
FROM client
WHERE client_id = 1;
```

**4. Попытка изменить первичный ключ модели**

```sql
UPDATE model
SET model_id = 100
WHERE model_id = 1;
```

Если комплектации ссылаются на эту модель, результат зависит от правила `ON UPDATE` внешнего ключа между `config` и `model`.

- При `RESTRICT` или `NO ACTION` операция будет отклонена.
- При `CASCADE` связанные значения внешних ключей могут обновиться автоматически.

**5. Попытка изменить первичный ключ комплектации**

```sql
UPDATE config
SET config_id = 100
WHERE config_id = 1;
```

Проверьте правило `ON UPDATE` внешнего ключа между `car` и `config`.

**6. Попытка изменить первичный ключ автомобиля**

```sql
UPDATE car
SET car_id = 100
WHERE car_id = 1;
```

Проверьте правила `ON UPDATE` внешних ключей, связывающих `car` с `sale` и `booking`.

Для проверки каскадного обновления используйте тестовые записи. В рабочих базах первичные ключи обычно не изменяют.

**7. Попытка указать несуществующий внешний ключ**

```sql
UPDATE car
SET config_id = 999999
WHERE car_id = 3;
```

Если комплектации с `config_id = 999999` нет, MySQL отклонит операцию из-за нарушения ограничения внешнего ключа.

Проверка результата:

```sql
SELECT *
FROM car
WHERE car_id = 3;
```

### Проверка каскадного обновления

Чтобы узнать действующие правила внешних ключей, выполните:

```sql
SHOW CREATE TABLE autosalon.config;
SHOW CREATE TABLE autosalon.car;
SHOW CREATE TABLE autosalon.booking;
SHOW CREATE TABLE autosalon.sale;
```

Найдите ограничения `CONSTRAINT` и изучите значения `ON UPDATE` и `ON DELETE`.

Если для внешнего ключа установлено `ON UPDATE CASCADE`, изменение родительского первичного ключа должно автоматически обновить связанные значения внешнего ключа в дочерней таблице.

После каждого действия зафиксируйте:

- какие операции выполнились успешно;
- какие операции были отклонены;
- в каких случаях сработал `ON UPDATE CASCADE`;
- почему нельзя указать несуществующий идентификатор внешнего ключа.
