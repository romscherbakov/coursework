# Практическая работа: Операции с данными в MySQL

## База данных «Автосалон»

**Цель работы:** научиться добавлять, изменять и удалять данные, проверять работу `AUTO_INCREMENT` и разбираться в связях между таблицами.

## Подготовка

Работа выполняется в базе данных `autosalon`.

Используются таблицы:

- `model` — модели автомобилей;
- `config` — комплектации;
- `car` — автомобили;
- `client` — клиенты;
- `employee` — сотрудники;
- `booking` — бронирования;
- `sale` — продажи.

Выберите базу данных:

```sql
USE autosalon;
```

Перед началом изучите структуру таблиц и связи между ними. Выполняйте задания по порядку. Если MySQL присвоил записи другие ID, используйте фактические значения из результатов `SELECT`.

## Часть 1. Добавление данных — `INSERT`

### Задание 1. Добавьте данные

1. Добавьте две модели автомобилей в `model`.
2. Добавьте две комплектации в `config`, связав каждую с существующей моделью.
3. Добавьте три автомобиля в `car`, указав существующие комплектации. Не указывайте `car_id` — MySQL должен присвоить его автоматически.
4. Добавьте двух клиентов в `client`.
5. Добавьте двух сотрудников в `employee`.
6. Создайте одну продажу в `sale` и одно бронирование в `booking`, используя существующие записи автомобилей, клиентов и сотрудников.

**Важно:** один автомобиль будет продан, второй — забронирован, третий останется свободным. Запомните ID этих автомобилей — они понадобятся в следующих частях.

Проверьте результат с помощью `SELECT`:

```sql
SELECT * FROM model;
SELECT * FROM config;
SELECT * FROM car;
SELECT * FROM client;
SELECT * FROM employee;
SELECT * FROM sale;
SELECT * FROM booking;
```

**Вопрос:** почему для новых записей обычно не нужно указывать значение первичного ключа с `AUTO_INCREMENT`?

## Часть 2. Удаление данных — `DELETE`

### Задание 2. Проверьте ограничения при удалении

Попробуйте выполнить следующие действия:

1. Удалить модель, для которой создана комплектация.
2. Удалить комплектацию, которая используется автомобилем.
3. Удалить проданный автомобиль.
4. Удалить забронированный автомобиль.
5. Удалить клиента, на которого оформлена продажа или бронирование.
6. Удалить сотрудника, указанного в продаже или бронировании.

Для каждого действия запишите результат: удаление прошло успешно или MySQL выдал ошибку.

**Важно:** не удаляйте свободный третий автомобиль до выполнения части 3.

**Вопрос:** почему MySQL запрещает удалять некоторые записи, если на них ссылаются другие таблицы?

## Часть 3. Изменение данных — `UPDATE`

### Задание 3. Измените обычные данные

1. Измените название одной модели в `model`.
2. Измените цену одной комплектации в `config`.
3. Измените контактные данные одного клиента в `client`.

После каждого изменения проверьте результат с помощью `SELECT`.

### Задание 4. Измените первичные ключи

Попробуйте изменить первичный ключ:

1. У модели, на которую ссылается комплектация.
2. У комплектации, которая используется автомобилем.
3. У автомобиля, на который ссылается продажа или бронирование.

Используйте реальные ID из своей базы. После каждого изменения проверьте, что произошло с записями в связанных таблицах.

**Вопрос:** что означает `ON UPDATE CASCADE` и как оно влияет на связанные записи?

### Задание 5. Проверьте внешний ключ

Попробуйте назначить свободному автомобилю несуществующую комплектацию:

```sql
UPDATE car
SET config_id = 999999
WHERE car_id = <ID_свободного_автомобиля>;
```

Вместо `<ID_свободного_автомобиля>` укажите фактический ID автомобиля.

Проверьте результат и объясните, почему MySQL разрешил или запретил изменение.

### Задание 6. Удалите свободный автомобиль

Теперь удалите автомобиль, у которого нет продажи и бронирования:

```sql
DELETE FROM car
WHERE car_id = <ID_свободного_автомобиля>;
```

Проверьте, что запись удалена.

## Часть 4. Контрольные вопросы

Ответьте своими словами.

1. Для чего нужен `AUTO_INCREMENT`?
2. Чем первичный ключ отличается от внешнего?
3. Почему нельзя удалить запись, на которую ссылаются другие таблицы?
4. Чем отличаются `ON DELETE RESTRICT` и `ON DELETE CASCADE`?
5. Что происходит при `ON UPDATE CASCADE`?
6. Почему MySQL запрещает указать несуществующий ID в поле внешнего ключа?
