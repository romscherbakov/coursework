# 🐧 Лабораторная работа № 8 — Восстановление базы данных MySQL из резервной копии

## Цель работы

Освоить процесс резервного копирования и восстановления базы данных MySQL. Научиться экспортировать базу данных из OpenPanel Server, передавать SQL-файл на сервер Ubuntu и восстанавливать данные в MySQL 8.4, работающем в Docker-контейнере.

## Необходимое программное обеспечение

- Ubuntu Server (виртуальная машина).
- Docker Engine.
- Docker Compose Plugin.
- Работающий Docker-контейнер `mysql84` с MySQL 8.4.
- OpenPanel Server с доступной базой данных `test3`.
- MobaXterm для передачи файлов по SFTP.

## 1. Подготовка к работе

В предыдущей лабораторной работе был развёрнут сервер MySQL 8.4 в Docker-контейнере.

В данной работе мы будем использовать уже созданную инфраструктуру. Повторная установка MySQL и создание Docker-контейнера не требуются.

Проверьте состояние контейнера:

```bash
docker compose ps
```

Убедитесь, что контейнер `mysql84` имеет статус `Up` и проверка работоспособности завершилась успешно (`healthy`).

Если контейнер остановлен, запустите его.

## 2. Экспорт базы данных из OpenPanel Server

На этом этапе необходимо получить резервную копию базы данных `test3` в формате SQL.

1. Откройте веб-интерфейс OpenPanel Server.
2. Перейдите в раздел управления базами данных.
3. Найдите базу данных `test3`.
4. Выберите действие **Export (Экспорт)**.
5. В качестве формата экспорта выберите **SQL (.sql)**.
6. Запустите экспорт и дождитесь завершения загрузки файла.

В результате на локальном компьютере должен появиться файл резервной копии:

```text
test3.sql
```

**Примечание:** в зависимости от версии и настроек OpenPanel расположение раздела экспорта может отличаться. В актуальной версии OpenPanel действие Export доступно непосредственно в списке баз данных.

Рекомендуется использовать обычный SQL-файл, а не архив GZIP, чтобы на данном этапе не добавлять операции распаковки.

## 3. Передача SQL-файла на виртуальную машину Ubuntu

Теперь необходимо передать полученный файл `test3.sql` с рабочего компьютера на виртуальную машину Ubuntu.

Для передачи воспользуемся SFTP в программе MobaXterm.

### 3.1. Подключение к виртуальной машине

1. Запустите MobaXterm.
2. Откройте ранее созданное SSH-подключение к виртуальной машине Ubuntu.
3. Убедитесь, что подключение установлено.

В левой части окна MobaXterm должна отображаться файловая система удалённой Ubuntu.

### 3.2. Передача файла

1. Найдите скачанный ранее файл `test3.sql` на локальном компьютере.
2. В файловой системе Ubuntu перейдите в домашний каталог пользователя:

```text
/home/user/
```

3. Перетащите файл `test3.sql` из локальной файловой системы в удалённый каталог Ubuntu.

После передачи файл должен находиться по следующему пути:

```text
/home/user/test3.sql
```

### 3.3. Проверка наличия файла

Перейдите в терминал Ubuntu и выполните:

```bash
ls -lh /home/user/test3.sql
```

Команда позволяет проверить наличие файла и определить его размер.

Дополнительно можно определить тип файла:

```bash
file /home/user/test3.sql
```

Убедитесь, что файл существует и его размер не равен нулю.

**Важно!** Не переименовывайте файл и не изменяйте его содержимое до завершения восстановления базы данных.

## 4. Создание пустой базы данных test3

Перед восстановлением необходимо создать пустую базу данных, в которую будут импортированы данные из резервной копии.

Перейдите в каталог проекта:

```bash
cd /opt/mysql
```

Подключитесь к MySQL под пользователем `root`:

```bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора MySQL, созданный в предыдущей лабораторной работе.

После успешного подключения появится приглашение:

```text
mysql>
```

### 4.1. Создание базы данных

Выполните SQL-запрос:

```sql
CREATE DATABASE test3
CHARACTER SET utf8mb4;
```

В результате MySQL создаст новую пустую базу данных `test3`.

### 4.2. Проверка создания базы данных

Выполните:

```sql
SHOW DATABASES;
```

В списке должна присутствовать база данных `test3`.

Проверьте, что в ней пока отсутствуют таблицы:

```sql
USE test3;
SHOW TABLES;
```

Ожидаемый результат:

```text
Empty set
```

Это означает, что база создана, но таблицы и данные ещё не импортированы.

Выйдите из MySQL Client:

```sql
exit;
```

## 5. Восстановление базы данных из SQL-файла

На данном этапе необходимо выполнить импорт содержимого файла `test3.sql` в созданную базу данных `test3`.

Для этого воспользуемся клиентом MySQL, запущенным непосредственно внутри Docker-контейнера.

### 5.1. Выполнение импорта

Находясь в каталоге `/opt/mysql`, выполните:

```bash
docker compose exec -T mysql sh -c \
'exec mysql -uroot -p"$(cat /run/secrets/mysql_root_password)" test3' \
< /home/user/test3.sql
```

Разберём команду:

| Элемент | Назначение |
|---|---|
| `docker compose exec` | Выполнение команды внутри работающего контейнера |
| `-T` | Отключение псевдотерминала для корректной передачи SQL-файла через стандартный ввод |
| `mysql` | Запуск клиента MySQL |
| `-uroot` | Подключение под пользователем `root` |
| `-p...` | Получение пароля из Docker Secret |
| `test3` | Выбор базы данных для импорта |
| `< /home/user/test3.sql` | Передача содержимого SQL-файла на вход клиенту MySQL |

**Примечание:** пароль берётся из файла `/run/secrets/mysql_root_password`, который уже используется в конфигурации Docker Compose из предыдущей лабораторной работы.

Если импорт завершился успешно, клиент MySQL не должен вывести сообщений об ошибках.

> Будет только выведено предупреждение: `mysql: [Warning] Using a password on the command line interface can be insecure.` Это не ошибка.

> Важно! Приведённая команда предполагает, что SQL-файл содержит определения таблиц и данные, но не переключается самостоятельно на другую базу через `USE`. Если в дампе присутствуют команды `CREATE DATABASE` или `USE`, необходимо предварительно проверить их содержимое и целевую базу данных.

## 6. Проверка восстановленной базы данных

После завершения импорта необходимо убедиться, что база данных восстановлена корректно.

### 6.1. Подключение к MySQL

Выполните:

```bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора.

### 6.2. Проверка наличия базы данных

Выполните:

```sql
SHOW DATABASES;
```

Убедитесь, что база `test3` присутствует в списке.

### 6.3. Проверка восстановленных таблиц

Выберите базу данных:

```sql
USE test3;
```

Выведите список таблиц:

```sql
SHOW TABLES;
```

В результате должны отобразиться таблицы восстановленной базы данных.

### 6.4. Проверка содержимого таблиц

Для проверки количества записей выполните запрос к одной из таблиц.

Например, если в восстановленной базе присутствует таблица `workers`:

```sql
SELECT COUNT(*) FROM workers;
```

Посмотрите несколько записей:

```sql
SELECT * FROM workers LIMIT 10;
```

Сравните результат с исходной базой данных `test3` в OpenPanel Server.

Количество записей и содержимое таблиц должны соответствовать исходной базе с учётом возможных изменений, произошедших после создания резервной копии.

Выйдите из MySQL Client:

```sql
exit;
```

## 7. Проверка сохранности восстановленных данных

В предыдущей лабораторной работе было организовано постоянное хранение файлов MySQL на RAID-1.

Проверим, что восстановленные данные находятся в постоянном хранилище и не зависят от жизненного цикла Docker-контейнера.

### 7.1. Проверка каталога данных

Выполните:

```bash
sudo ls -lah /mnt/raid1/mysql/data/
```

В каталоге должны находиться файлы и подкаталоги MySQL.

### 7.2. Перезапуск контейнера

Выполните:

```bash
docker compose restart
```

Дождитесь завершения запуска и проверьте состояние:

```bash
docker compose ps
```

Убедитесь, что контейнер получил статус `healthy`.

### 7.3. Повторная проверка базы данных

Подключитесь к MySQL:

```bash
docker compose exec mysql mysql -uroot -p
```

Выполните:

```sql
USE test3;
SHOW TABLES;
```

Убедитесь, что таблицы сохранились после перезапуска контейнера.

Дополнительно проверьте содержимое одной из таблиц:

```sql
SELECT COUNT(*) FROM workers;
```

Выйдите из MySQL Client:

```sql
exit;
```

Это подтверждает, что восстановленные данные сохраняются в постоянном хранилище RAID-1.
