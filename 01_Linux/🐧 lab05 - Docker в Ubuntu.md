# Лабораторная работа № 5 — Установка и первоначальная настройка Docker в Ubuntu

## Цель работы

Установить Docker Engine в виртуальную машину Ubuntu, настроить доступ к Docker для обычного пользователя, проверить работу Docker и освоить основные команды управления контейнерами. Запустить веб-сервер Nginx в контейнере и проверить его доступность из основной операционной системы Windows.

## Необходимое оборудование и ПО

- Виртуальная машина Ubuntu в Oracle VirtualBox.
- Пользователь Ubuntu `user` с правами `sudo`.
- Настроенный SSH-доступ к Ubuntu.
- MobaXterm для подключения к виртуальной машине.
- Доступ виртуальной машины в Интернет.
- Браузер в основной операционной системе Windows.

**Регистрация не требуется.** Аккаунты Docker Hub и GitHub не нужны. Используемые в работе образы `hello-world` и `nginx:alpine` общедоступны и загружаются без авторизации.

## Результат работы

Docker Engine установлен и запущен. Пользователь `user` может выполнять команды Docker без `sudo`. Студент умеет загружать образы, создавать, просматривать, запускать, останавливать и удалять контейнеры. Веб-сервер Nginx запущен в контейнере и доступен из браузера Windows по IP-адресу виртуальной машины Ubuntu.

## 1. Подготовка виртуальной машины

Перед началом работы необходимо настроить сетевое подключение виртуальной машины.

### 1.1. Настройка сети VirtualBox

1. Выключите виртуальную машину Ubuntu.
2. Откройте настройки виртуальной машины в VirtualBox.
3. Перейдите в раздел **Сеть → Адаптер 1**.
4. В поле «Тип подключения» выберите **Сетевой мост (Bridged Adapter)**.
5. В поле «Имя» выберите сетевой адаптер основного компьютера, через который осуществляется подключение к локальной сети.
6. Сохраните настройки и запустите Ubuntu.

Режим сетевого моста позволяет виртуальной машине получить собственный IP-адрес в локальной сети. Благодаря этому к сервисам, запущенным в Ubuntu, можно обращаться с основного компьютера и других устройств, которым разрешён сетевой доступ.

### 1.2. Подключение к Ubuntu через MobaXterm

Войдите в Ubuntu и определите её IP-адрес:

```bash
hostname -I
```

Запишите полученный IP-адрес.

Откройте MobaXterm на основном компьютере:

1. Нажмите **Session**.
2. Выберите **SSH**.
3. В поле **Remote host** укажите IP-адрес виртуальной машины Ubuntu.
4. Установите флажок **Specify username** и укажите `user`.
5. В поле **Port** укажите `22`.
6. Нажмите **OK**.
7. При первом подключении подтвердите доверие к SSH-серверу.
8. Введите пароль пользователя `user`.

После успешного подключения откроется терминал Ubuntu.

**Все дальнейшие команды лабораторной работы выполняются в терминале MobaXterm.**

### 1.3. Проверка системы и Интернета

Проверьте подключение к Интернету:

```bash
ping -c 4 ubuntu.com
```

Посмотрите версию Ubuntu и архитектуру:

```bash
lsb_release -a
dpkg --print-architecture
```

Для типовой виртуальной машины на ПК ожидается архитектура `amd64`.

## 2. Установка Docker Engine

Установим Docker Engine из официального репозитория Docker.

### 2.1. Подготовка системы

Выполните команды:

```bash
sudo apt update
sudo apt install ca-certificates curl
```

Назначение компонентов:

- `apt update` — обновляет сведения о доступных пакетах.
- `ca-certificates` — обеспечивает проверку сертификатов HTTPS.
- `curl` — позволяет загружать файлы из Интернета.

### 2.2. Добавление ключа Docker

Выполните команды:

```bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

Ключ позволяет менеджеру пакетов проверять подлинность пакетов из репозитория Docker.

### 2.3. Добавление официального репозитория

Для установки Docker необходимо добавить его официальный репозиторий в список источников пакетов Ubuntu.

**Шаг 1. Определение кодового имени Ubuntu**

Выполните команду:

```bash
. /etc/os-release && echo "$VERSION_CODENAME"
```

Запомните полученное значение.

Например:
- Ubuntu 24.04 — `noble`;
- Ubuntu 22.04 — `jammy`.

**Шаг 2. Определение архитектуры системы**

Выполните команду:

```bash
dpkg --print-architecture
```

Запомните полученное значение. Для типовой виртуальной машины на ПК это `amd64`.

**Шаг 3. Создание файла репозитория**

Откройте файл конфигурации в текстовом редакторе:

```bash
sudo nano /etc/apt/sources.list.d/docker.sources
```

Скопируйте приведённый ниже текст и вставьте его в открытый редактор:

```ini
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: noble
Components: stable
Architectures: amd64
Signed-By: /etc/apt/keyrings/docker.asc
```

**Важно:** замените `noble` на кодовое имя своей версии Ubuntu, полученное на шаге 1, а `amd64` — на архитектуру, полученную на шаге 2.

**Шаг 4. Сохранение файла**

В редакторе `nano`:

1. Нажмите `Ctrl + O` для сохранения файла.
2. Нажмите `Enter` для подтверждения имени файла.
3. Нажмите `Ctrl + X` для выхода из редактора.

**Шаг 5. Обновление списка пакетов**

Выполните команду:

```bash
sudo apt update
```

Если команда завершилась без ошибок, официальный репозиторий Docker добавлен успешно.

### 2.4. Установка компонентов Docker

Выполните команду:

```bash
sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

Подтвердите установку, если `apt` запросит подтверждение.

| Компонент | Назначение |
|---|---|
| `docker-ce` | Docker Engine — служба управления контейнерами |
| `docker-ce-cli` | Командная строка `docker` |
| `containerd.io` | Среда выполнения контейнеров |
| `docker-buildx-plugin` | Инструменты сборки образов |
| `docker-compose-plugin` | Управление многоконтейнерными приложениями |

## 3. Проверка установки и службы Docker

Проверьте версию Docker:

```bash
docker --version
```

Проверьте состояние службы:

```bash
sudo systemctl status docker
```

Найдите состояние:

```text
Active: active (running)
```

Если служба не запущена, выполните:

```bash
sudo systemctl enable --now docker
```

Команда включает автозапуск Docker при старте Ubuntu и запускает службу сейчас.

Проверьте взаимодействие клиента с сервером Docker:

```bash
sudo docker version
```

В выводе должны присутствовать разделы `Client` и `Server`.

## 4. Настройка доступа пользователя к Docker

По умолчанию для выполнения команд Docker требуются права администратора (`sudo`).

Чтобы пользователь `user` мог работать с Docker без постоянного ввода `sudo`, добавим его в специальную группу `docker`.

Выполните:

```bash
sudo usermod -aG docker user
```

Пояснение:

- `usermod` — изменение параметров пользователя.
- `-aG` — добавление пользователя в дополнительную группу без удаления из остальных групп.
- `docker` — группа, предоставляющая доступ к управлению Docker.
- `user` — имя пользователя Ubuntu.

**Важно:** изменения вступают в силу после повторного входа пользователя в систему.

Закройте SSH-соединение:

```bash
exit
```

Заново подключитесь к Ubuntu через MobaXterm.

Проверьте членство пользователя в группах:

```bash
groups
```

В списке должна присутствовать группа `docker`.

Теперь проверьте работу Docker без `sudo`:

```bash
docker version
```

В выводе должны присутствовать разделы `Client` и `Server`.

Если команда выполняется без ошибки доступа к Docker daemon, настройка выполнена успешно.

## 5. Первый контейнер: hello-world

Запустите тестовый контейнер:

```bash
docker run hello-world
```

При первом запуске Docker загрузит образ из публичного реестра Docker Hub.

После этого появится сообщение, начинающееся примерно так:

```text
Hello from Docker!
This message shows that your installation appears to be working correctly.
```

Это означает, что Docker установлен и может запускать контейнеры.

Что произошло:

1. Docker проверил, есть ли образ `hello-world` на виртуальной машине.
2. Если образ отсутствовал, Docker скачал его из Docker Hub.
3. На основе образа был создан контейнер.
4. Контейнер выполнил программу, вывел сообщение и завершил работу.

Входить в Docker Hub для загрузки этого общедоступного образа не требуется.

## 6. Просмотр образов и контейнеров

Посмотрите список загруженных образов:

```bash
docker images
```

Посмотрите список работающих контейнеров:

```bash
docker ps
```

Контейнер `hello-world` не отображается, потому что уже завершил работу.

Посмотрите список всех контейнеров, в том числе остановленных:

```bash
docker ps -a
```

В списке должен присутствовать `hello-world` со статусом `Exited`.

## 7. Практика: запуск веб-сервера Nginx в Docker

В этой части работы запустим веб-сервер Nginx внутри Docker-контейнера и проверим его доступность из основной операционной системы Windows.

### 7.1. Запуск контейнера

Выполните команду:

```bash
docker run -d --name web-lab -p 8080:80 nginx:alpine
```

Пояснение параметров:

| Параметр | Назначение |
|---|---|
| `-d` | Запуск контейнера в фоновом режиме |
| `--name web-lab` | Имя контейнера |
| `-p 8080:80` | Публикация порта 80 контейнера на порту 8080 Ubuntu |
| `nginx:alpine` | Используемый образ Nginx |

Docker загрузит образ Nginx из Docker Hub, создаст контейнер и запустит веб-сервер.

Проверьте, что контейнер работает:

```bash
docker ps
```

В списке должен появиться `web-lab` со статусом `Up`.

### 7.2. Определение IP-адреса Ubuntu

Узнайте IP-адрес виртуальной машины:

```bash
hostname -I
```

Запишите IP-адрес Ubuntu. Если команда вывела несколько адресов, используйте адрес сетевого интерфейса, подключённого к локальной сети.

### 7.3. Проверка веб-сервера из Windows

Перейдите на основной компьютер с Windows.

Откройте браузер и введите адрес:

```text
http://IP-АДРЕС-UBUNTU:8080
```

Например, если IP-адрес Ubuntu — `192.168.1.120`, адрес будет выглядеть так:

```text
http://192.168.1.120:8080
```

Должна открыться стандартная стартовая страница Nginx с сообщением:

```text
Welcome to nginx!
```

Таким образом, мы убедились, что веб-сервер работает внутри Docker-контейнера и доступен из другой операционной системы по сети.

Если страница не открывается, проверьте:

- Работает ли контейнер: `docker ps`.
- Правильно ли указан IP-адрес Ubuntu.
- Доступен ли порт 8080 через брандмауэр Ubuntu.
- Находятся ли Windows и Ubuntu в сетях, между которыми разрешено взаимодействие.

Если используется UFW и он активен, разрешите входящие подключения к порту 8080:

```bash
sudo ufw allow 8080/tcp
```

### 7.4. Просмотр журналов

Посмотрите журналы контейнера:

```bash
docker logs web-lab
```

После обращения к веб-серверу из браузера Windows в журналах можно увидеть информацию об обработанных запросах.

### 7.5. Остановка и повторный запуск

Остановите контейнер:

```bash
docker stop web-lab
```

Обновите страницу Nginx в браузере Windows. Веб-сервер должен стать недоступен.

Посмотрите состояние контейнера:

```bash
docker ps -a
```

Теперь запустите этот же контейнер:

```bash
docker start web-lab
```

Проверьте его состояние:

```bash
docker ps
```

Обновите страницу в браузере Windows. Страница Nginx снова должна открыться.

### 7.6. Удаление контейнера

Остановите и удалите контейнер:

```bash
docker stop web-lab
docker rm web-lab
```

Проверьте список контейнеров:

```bash
docker ps -a
```

Контейнер `web-lab` должен исчезнуть.

Образ Nginx при этом останется на виртуальной машине:

```bash
docker images
```

**Важно различать:**

- **Образ (image)** — шаблон, из которого создают контейнеры.
- **Контейнер (container)** — созданный на основе образа экземпляр приложения, который может работать или быть остановлен.

Удаление контейнера само по себе не удаляет образ.

## 8. Основные команды Docker

| Команда | Назначение |
|---|---|
| `docker version` | Версия и состояние клиента/сервера |
| `docker images` | Список образов |
| `docker ps` | Список работающих контейнеров |
| `docker ps -a` | Список всех контейнеров |
| `docker run IMAGE` | Создать и запустить контейнер |
| `docker start NAME` | Запустить остановленный контейнер |
| `docker stop NAME` | Остановить контейнер |
| `docker logs NAME` | Посмотреть журналы контейнера |
| `docker inspect NAME` | Подробная информация о контейнере |
| `docker rm NAME` | Удалить остановленный контейнер |
| `docker rmi IMAGE` | Удалить образ |

## Примечания по безопасности

- Членство в группе `docker` фактически предоставляет пользователю привилегии уровня `root`. Поэтому добавлять в неё следует только доверенных пользователей.
- В лабораторной работе используется отдельная учебная виртуальная машина.
- Режим сетевого моста предоставляет Ubuntu отдельный IP-адрес в локальной сети. Учитывайте доступность виртуальной машины для других устройств этой сети.
- Публикация порта `8080` делает веб-сервер доступным по сети в пределах действующих сетевых правил.
