# 🐧 Лабораторная работа № 10 — Автоматизация резервного копирования MySQL

## Цель работы

Научиться автоматизировать резервное копирование базы данных MySQL в Linux.

Освоить написание Bash-скриптов, настройку планировщика заданий `cron`, создание сжатых резервных копий и управление сроками их хранения.

Научиться проверять целостность резервных копий и восстанавливать базу данных из автоматически созданного SQL-дампа.

## Необходимое программное обеспечение

- Ubuntu Server (виртуальная машина).
- Docker Engine.
- Docker Compose Plugin.
- Работающий Docker-контейнер `mysql84` с MySQL 8.4.
- Восстановленная база данных `test3` из лабораторной работы № 8.
- RAID-1, смонтированный в `/mnt/raid1`.
- Текстовый редактор `nano`.

## 1. Подготовка к работе

В предыдущих лабораторных работах был развёрнут сервер MySQL 8.4 в Docker-контейнере, восстановлена база данных `test3` и настроены пользователи с различными правами доступа.

В данной работе необходимо организовать автоматическое резервное копирование существующей базы данных.

Повторная установка MySQL и создание Docker-контейнера не требуются.

## 2. Подготовка каталога для резервных копий

Для хранения резервных копий создадим отдельный каталог в проекте MySQL.

Выполните:

```bash
sudo mkdir -p -v /opt/mysql/backup
```

Настроим доступ к каталогу:

```bash
sudo chmod 755 -v /opt/mysql/backup
```

Проверим результат:

```bash
sudo ls -ld /opt/mysql/backup
```

В результате должен отобразиться каталог с ограниченными правами доступа.

### 2.1. Структура каталогов проекта

После подготовки структура проекта должна выглядеть следующим образом:

```text
/opt/mysql/
├── docker-compose.yaml
├── backup_mysql.sh
├── backup/
│   ├── test3_2026-11-25_02-00-00.sql.gz
│   ├── test3_2026-11-24_02-00-00.sql.gz
│   └── backup.log
├── config/
│   └── my.cnf
└── secrets/
    └── mysql_root_password.txt
```

Назначение каталогов:

| Каталог / файл | Назначение |
|---|---|
| `/opt/mysql/` | Файлы проекта Docker Compose |
| `backup/` | Хранение резервных копий |
| `backup_mysql.sh` | Bash-скрипт резервного копирования |
| `backup.log` | Журнал выполнения резервного копирования |
| `config/` | Конфигурация MySQL |
| `secrets/` | Файлы с конфиденциальными данными |

Обратите внимание: в данной работе резервные копии будут храниться отдельно от файлов базы данных MySQL.

При этом каталог `/opt/mysql/backup` располагается на файловой системе Ubuntu, а не непосредственно внутри Docker-контейнера.

## 3. Создание Bash-скрипта резервного копирования

Для автоматизации резервного копирования создадим скрипт `backup_mysql.sh`.

Перейдите в каталог проекта:

```bash
cd /opt/mysql
```

Создайте файл:

```bash
sudo nano backup_mysql.sh
```

Добавьте следующий код:

```bash
#!/bin/bash

# Завершение работы при ошибках
set -Eeuo pipefail

# Каталог проекта Docker Compose
PROJECT_DIR="/opt/mysql"

# Имя базы данных
DB_NAME="test3"

# Каталог резервных копий
BACKUP_DIR="/opt/mysql/backup"

# Файл журнала
LOG_FILE="${BACKUP_DIR}/backup.log"

# Дата и время создания резервной копии
TIMESTAMP=$(date +"%Y-%m-%d_%H-%M-%S")

# Имя резервной копии
BACKUP_FILE="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.sql.gz"

# Переход в каталог проекта
cd "$PROJECT_DIR"

# Создание каталога, если он отсутствует
mkdir -p "$BACKUP_DIR"

# Запись вывода скрипта в журнал
exec >> "$LOG_FILE" 2>&1

echo "========================================"
echo "Начало резервного копирования: $(date)"
echo "База данных: ${DB_NAME}"

# Защита от одновременного запуска нескольких копий скрипта
exec 9>/run/lock/mysql-backup.lock

if ! flock -n 9; then
    echo "ОШИБКА: резервное копирование уже выполняется"
    exit 1
fi

# Временный файл для формирования резервной копии
TMP_FILE=$(mktemp "${BACKUP_DIR}/.${DB_NAME}_XXXXXX")

# Удаление временного файла при завершении или ошибке
cleanup() {
    if [[ -n "${TMP_FILE:-}" && -f "$TMP_FILE" ]]; then
        rm -f -- "$TMP_FILE"
    fi
}

trap cleanup EXIT

# Экспорт базы данных и сжатие результата
if ! docker compose exec -T mysql sh -c \
    'exec mysqldump -uroot -p"$(cat /run/secrets/mysql_root_password)" \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --no-tablespaces test3' \
    | gzip -c > "$TMP_FILE"; then

    echo "ОШИБКА: не удалось создать резервную копию"
    exit 1
fi

# Проверка целостности GZIP-архива
if ! gzip -t "$TMP_FILE"; then
    echo "ОШИБКА: архив повреждён"
    exit 1
fi

# Перемещение временного файла в итоговый каталог
mv -- "$TMP_FILE" "$BACKUP_FILE"
TMP_FILE=""

echo "Резервная копия успешно создана:"
echo "$BACKUP_FILE"

# Вывод размера резервной копии
du -h "$BACKUP_FILE"

# Удаление старых резервных копий.
# Оставляем последние 7 файлов.
find "$BACKUP_DIR" \
    -maxdepth 1 \
    -type f \
    -name "${DB_NAME}_*.sql.gz" \
    -printf '%f\n' \
    | sort -r \
    | tail -n +8 \
    | while IFS= read -r OLD_FILE; do
        rm -f -- "${BACKUP_DIR}/${OLD_FILE}"
        echo "Удалена старая копия: ${OLD_FILE}"
    done

echo "Резервное копирование завершено: $(date)"
echo "========================================"
```

Сохраните файл и выйдите из редактора `nano`.

### 3.1. Разбор основных команд скрипта

В скрипте используются следующие команды и механизмы:

| Команда / параметр | Назначение |
|---|---|
| `#!/bin/bash` | Указывает интерпретатор Bash |
| `set -Eeuo pipefail` | Включает строгую обработку ошибок |
| `date` | Получение текущей даты и времени |
| `mkdir -p` | Создание каталога |
| `exec` | Перенаправление вывода в журнал |
| `flock` | Предотвращение одновременного запуска скрипта |
| `docker compose exec` | Выполнение команды внутри контейнера |
| `mysqldump` | Экспорт базы данных MySQL |
| `gzip` | Сжатие SQL-файла |
| `gzip -t` | Проверка целостности архива |
| `mktemp` | Создание временного файла |
| `mv` | Перемещение файла |
| `du -h` | Просмотр размера файла |
| `find` | Поиск файлов резервных копий |
| `sort` | Сортировка списка файлов |
| `tail` | Получение части списка файлов |
| `rm` | Удаление файлов |

### 3.2. Разбор команды mysqldump

Особое внимание обратите на команду:

```bash
mysqldump -uroot \
    -p"$(cat /run/secrets/mysql_root_password)" \
    --single-transaction \
    --routines \
    --triggers \
    --events \
    --no-tablespaces test3
```

Назначение параметров:

| Параметр | Назначение |
|---|---|
| `-uroot` | Подключение под пользователем `root` |
| `-p...` | Передача пароля администратора |
| `--single-transaction` | Создание согласованного снимка транзакционных таблиц |
| `--routines` | Экспорт хранимых процедур и функций |
| `--triggers` | Экспорт триггеров |
| `--events` | Экспорт событий MySQL |
| `--no-tablespaces` | Исключение информации о табличных пространствах |
| `test3` | Имя базы данных для экспорта |

**Важно!** Параметр `--single-transaction` обеспечивает согласованный экспорт прежде всего для таблиц InnoDB. Во время резервного копирования не следует выполнять операции изменения структуры таблиц.

Пароль администратора берётся из Docker Secret:

```text
/run/secrets/mysql_root_password
```

Это тот же файл, который использовался при развёртывании MySQL в лабораторной работе № 7.

Таким образом, пароль не требуется записывать непосредственно в Bash-скрипт.

### 3.3. Принцип формирования имени резервной копии

В скрипте используется команда:

```bash
TIMESTAMP=$(date +"%Y-%m-%d_%H-%M-%S")
```

Она формирует дату и время в следующем формате:

```text
2026-11-25_02-00-00
```

В результате имя резервной копии будет выглядеть следующим образом:

```text
test3_2026-11-25_02-00-00.sql.gz
```

Такой формат позволяет:
- Определить дату создания резервной копии.
- Определить время создания резервной копии.
- Упорядочить файлы по времени создания.
- Хранить несколько резервных копий одновременно.

### 3.4. Принцип хранения последних 7 резервных копий

В скрипте используется команда:

```bash
find "$BACKUP_DIR" \
    -maxdepth 1 \
    -type f \
    -name "${DB_NAME}_*.sql.gz"
```

Она находит файлы резервных копий базы `test3` непосредственно в каталоге `backup`.

Далее используется сортировка:

```bash
sort -r
```

Она располагает имена файлов в обратном алфавитном порядке. Поскольку дата записана в формате `ГГГГ-ММ-ДД`, такая сортировка соответствует хронологическому порядку.

Команда:

```bash
tail -n +8
```

оставляет все файлы, начиная с восьмого.

Таким образом, скрипт удаляет старые резервные копии, сохраняя последние семь.

**Важно!** Удаляются только файлы, соответствующие шаблону `test3_*.sql.gz`. Остальные файлы в каталоге не затрагиваются.

## 4. Настройка прав доступа и проверка скрипта

После создания файла необходимо предоставить ему права на выполнение.

Выполните:

```bash
sudo chown -v root:root /opt/mysql/backup_mysql.sh
```

Установите права:

```bash
sudo chmod -v 700 /opt/mysql/backup_mysql.sh
```

Проверьте результат:

```bash
ls -l /opt/mysql/backup_mysql.sh
```

Ожидаемый результат:

```text
-rwx------ 1 root root ... backup_mysql.sh
```

Это означает, что запускать и изменять скрипт может только пользователь `root`.

### 4.1. Ручной запуск резервного копирования

Перед настройкой автоматического запуска необходимо проверить работу скрипта вручную.

Выполните:

```bash
sudo /opt/mysql/backup_mysql.sh
```

Если операция завершилась успешно, в журнале появится сообщение:

```text
Резервная копия успешно создана:
```

Проверьте содержимое каталога:

```bash
sudo ls -lh /opt/mysql/backup/
```

В каталоге должен появиться файл примерно следующего вида:

```text
test3_2026-11-25_01-30-00.sql.gz
```

Размер файла зависит от количества данных в базе.

### 4.2. Проверка журнала выполнения

Для просмотра журнала выполните:

```bash
sudo cat /opt/mysql/backup/backup.log
```

Для просмотра последних записей:

```bash
sudo tail -n 20 /opt/mysql/backup/backup.log
```

В журнале должны присутствовать:
- Дата и время начала операции.
- Название базы данных.
- Результат создания резервной копии.
- Размер созданного файла.
- Информация об удалении старых копий.
- Дата и время завершения операции.

Журнал позволяет администратору проверить, когда выполнялось резервное копирование и возникали ли ошибки.

## 5. Проверка резервной копии

Создание файла ещё не означает, что резервная копия пригодна для восстановления.

Необходимо проверить целостность архива.

### 5.1. Проверка формата файла

Выполните:

```bash
file /opt/mysql/backup/test3_*.sql.gz
```

В результате должен отображаться тип файла:

```text
gzip compressed data
```

### 5.2. Проверка целостности GZIP-архива

Выполните:

```bash
sudo gzip -t /opt/mysql/backup/test3_*.sql.gz
```

Если архив не повреждён, команда завершится без вывода сообщений об ошибках.

Дополнительно можно посмотреть содержимое SQL-файла без его распаковки на диск:

```bash
sudo gzip -dc /opt/mysql/backup/test3_*.sql.gz | head -n 30
```

В результате должны отобразиться первые строки SQL-дампа.

**Примечание:** резервная копия создаётся без команд `CREATE DATABASE` и `USE`. Это позволяет при восстановлении самостоятельно выбрать целевую базу данных.

## 6. Настройка автоматического запуска через cron

До настоящего момента резервное копирование выполнялось вручную.

Теперь необходимо настроить автоматический запуск скрипта по расписанию.

Для этого используется планировщик заданий `cron`.

Cron — стандартный механизм Linux, позволяющий выполнять команды и скрипты в заданное время без участия пользователя.

### 6.1. Проверка службы cron

Проверьте состояние службы:

```bash
systemctl status cron
```

Если служба не запущена, выполните:

```bash
sudo systemctl enable --now cron
```

Параметр `enable` обеспечивает автоматический запуск службы при загрузке Ubuntu.

Параметр `--now` запускает службу немедленно.

### 6.2. Открытие таблицы заданий root

Резервное копирование будет выполняться от имени системного пользователя `root`.

Откройте его таблицу заданий:

```bash
sudo crontab -e
```

Если система предложит выбрать текстовый редактор, выберите `nano`.

В конец файла добавьте строку:

```cron
0 2 * * * /opt/mysql/backup_mysql.sh
```

Сохраните изменения и выйдите из редактора.

### 6.3. Разбор расписания cron

Строка:

```cron
0 2 * * * /opt/mysql/backup_mysql.sh
```

состоит из пяти временных параметров и команды.

| Позиция | Значение | Назначение |
|---|---|---|
| 1 | `0` | Минута |
| 2 | `2` | Час |
| 3 | `*` | Любой день месяца |
| 4 | `*` | Любой месяц |
| 5 | `*` | Любой день недели |

Таким образом, резервное копирование будет выполняться ежедневно в 02:00 по времени операционной системы Ubuntu.

Примеры других расписаний:

```cron
0 3 * * *       # Каждый день в 03:00
0 */6 * * *     # Каждые 6 часов
30 1 * * 1      # Каждый понедельник в 01:30
0 2 * * 0       # Каждое воскресенье в 02:00
```

### 6.4. Проверка настроенного задания

Выполните:

```bash
sudo crontab -l
```

В результате должна отобразиться добавленная строка:

```cron
0 2 * * * /opt
