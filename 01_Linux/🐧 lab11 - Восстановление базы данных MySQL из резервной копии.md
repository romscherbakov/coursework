# 🐧 Лабораторная работа № 11 — Восстановление базы данных MySQL из резервной копии

## Цель работы

Научиться восстанавливать базу данных MySQL из ранее созданной резервной копии.

Освоить работу со сжатыми SQL-дампами, проверку целостности архивов GZIP, создание базы данных и импорт данных в MySQL 8.4, работающий в Docker-контейнере.

Научиться проверять корректность восстановления структуры таблиц и содержащихся в них данных.

## Необходимое программное обеспечение

- Ubuntu Server 24.04 LTS (виртуальная машина).
- Docker Engine.
- Docker Compose Plugin.
- Работающий Docker-контейнер `mysql84` с MySQL 8.4.
- Текстовый редактор `nano`.
- Резервная копия базы данных `test3`.

## 1. Исходные данные

В предыдущих лабораторных работах был развёрнут сервер MySQL 8.4 в Docker-контейнере `mysql84` и подготовлена база данных `test3`.

Для выполнения данной работы необходимо восстановить базу `test3` из ранее созданной резервной копии.

**Резервная копия уже размещена на Ubuntu Server** в каталоге:

```text
/opt/mysql/backup/
```

Используемый файл:

```text
test3_2026-11-24_02-00-00.sql.gz
```

Разберём название файла:

| Элемент | Назначение |
|---|---|
| `test3` | Имя исходной базы данных |
| `2026-11-24` | Дата создания резервной копии |
| `02-00-00` | Время создания резервной копии |
| `.sql` | SQL-дамп базы данных |
| `.gz` | Сжатие файла с использованием GZIP |

SQL-дамп содержит SQL-команды, необходимые для восстановления структуры таблиц и данных.

В данной работе архив не требуется передавать с Windows или распаковывать на отдельный компьютер.

**Важно!** Исходная база `test3` уже существует. Мы не будем удалять её или восстанавливать данные поверх неё. Для восстановления создадим отдельную базу `test3_restore`.

## 2. Проверка резервной копии

Перед восстановлением необходимо убедиться, что файл присутствует на сервере и не повреждён.

### 2.1. Проверка наличия файла

Перейдите в каталог резервных копий:

```bash
cd /opt/mysql/backup
```

Посмотрите содержимое каталога:

```bash
ls -lh
```

Убедитесь, что в списке присутствует файл:

```text
test3_2026-11-24_02-00-00.sql.gz
```

Если для просмотра каталога требуются права администратора, используйте:

```bash
sudo ls -lh /opt/mysql/backup/
```

### 2.2. Проверка формата файла

Выполните:

```bash
file test3_2026-11-24_02-00-00.sql.gz
```

В результате должен отображаться тип файла, содержащий:

```text
gzip compressed data
```

### 2.3. Проверка целостности архива

Выполните:

```bash
gzip -t test3_2026-11-24_02-00-00.sql.gz
```

Если архив не повреждён, команда завершится без вывода сообщений об ошибках.

Если у пользователя нет прав на чтение файла, выполните проверку с правами администратора:

```bash
sudo gzip -t /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz
```

### 2.4. Просмотр содержимого SQL-дампа

Посмотрим первые строки SQL-файла, не распаковывая архив на диск:

```bash
gzip -dc test3_2026-11-24_02-00-00.sql.gz | head -n 30
```

Если для чтения файла требуются права администратора:

```bash
sudo gzip -dc /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz | head -n 30
```

Убедитесь, что содержимое представляет собой SQL-команды.

**Важно!** Не удаляйте исходный архив и не изменяйте его содержимое. Он понадобится для восстановления базы данных.

## 4. Создание пустой базы данных test3_restore

Для восстановления SQL-дампа необходимо подготовить базу данных, в которую будут импортированы таблицы и записи.

Подключитесь к MySQL:

```bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора MySQL.

Создайте базу данных:

```sql
CREATE DATABASE test3_restore
CHARACTER SET utf8mb4
COLLATE utf8mb4_unicode_ci;
```

Проверьте результат:

```sql
SHOW DATABASES;
```

База `test3_restore` должна появиться в списке.

Посмотрите её параметры:

```sql
SHOW CREATE DATABASE test3_restore;
```

Выйдите из MySQL Client:

```sql
exit;
```

## 5. Восстановление базы данных из SQL-дампа

Теперь выполним импорт SQL-файла в созданную базу данных.

Перейдите в каталог проекта:

```bash
cd /opt/mysql
```

Выполните команду:

```bash
sudo gzip -dc /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz \
| docker compose exec -T mysql sh -c \
'exec mysql -uroot -p"$(cat /run/secrets/mysql_root_password)" test3_restore'
```

Команда выполняет сразу несколько действий:

1. `gzip -dc` читает сжатый архив и выводит его содержимое в несжатом виде.
2. Символ `|` передаёт полученный SQL-текст следующей команде.
3. `docker compose exec -T mysql` запускает команду внутри контейнера MySQL без выделения псевдотерминала.
4. `mysql` подключается к серверу от имени пользователя `root`.
5. Пароль администратора считывается из Docker Secret.
6. Имя `test3_restore` указывает базу данных, в которую импортируются SQL-команды.

Таким образом, архив распаковывается непосредственно в потоке передачи данных и не требует создания дополнительного несжатого файла на диске.

**Важно!**

- Исходный архив `test3_2026-11-24_02-00-00.sql.gz` остаётся нетронутым.
- Для импорта используется пользователь MySQL `root`, поскольку восстановление может включать создание таблиц, индексов, триггеров и других объектов.
- Команда рассчитана на SQL-дамп, который не содержит самостоятельного переключения на другую базу данных через `USE`.
- Команда предполагает, что текущий пользователь имеет доступ к Docker. Если доступ к Docker предоставлен только через `sudo`, необходимо использовать соответствующий запуск Docker Compose с правами администратора.

При успешном выполнении MySQL обычно не выводит отдельное сообщение о завершении импорта. Результат необходимо проверить следующими командами.

## 6. Проверка восстановления базы данных

После завершения импорта необходимо убедиться, что структура и данные восстановлены корректно.

### 6.1. Проверка наличия таблиц

Подключитесь к MySQL:

```bash
docker compose exec mysql mysql -uroot -p
```

Выберите восстановленную базу данных:

```sql
USE test3_restore;
```

Выведите список таблиц:

```sql
SHOW TABLES;
```

Убедитесь, что в базе присутствуют все семь таблиц:

- `departments` — отделы;
- `projects` — проекты;
- `workers` — сотрудники;
- `tasks` — задачи;
- `salaries` — зарплаты;
- `tags` — теги;
- `tags_tasks` — связь задач с тегами.

### 6.2. Проверка количества записей

Выполните запросы:

```sql
SELECT COUNT(*) AS departments_count
FROM departments;

SELECT COUNT(*) AS projects_count
FROM projects;

SELECT COUNT(*) AS workers_count
FROM workers;

SELECT COUNT(*) AS tasks_count
FROM tasks;

SELECT COUNT(*) AS salaries_count
FROM salaries;

SELECT COUNT(*) AS tags_count
FROM tags;

SELECT COUNT(*) AS tags_tasks_count
FROM tags_tasks;
```

Запишите полученные результаты.

Для данной учебной базы ожидаются следующие значения:

| Таблица | Ожидаемое количество записей |
|---|---:|
| `departments` | 4 |
| `projects` | 10 |
| `workers` | 12 |
| `tasks` | 31 |
| `salaries` | 16 |
| `tags` | 20 |
| `tags_tasks` | 88 |

Количество записей позволяет проверить, что данные действительно были импортированы, а не только созданы пустые таблицы.

### 6.3. Проверка содержимого таблиц

Посмотрите несколько записей из восстановленной таблицы сотрудников:

```sql
SELECT *
FROM workers
LIMIT 10;
```

Посмотрите список отделов:

```sql
SELECT *
FROM departments;
```

Убедитесь, что запросы выполняются и возвращают данные.

### 6.4. Сравнение исходной и восстановленной баз

Теперь сравним количество записей в исходной базе `test3` и восстановленной базе `test3_restore`.

Выполните:

```sql
SELECT 'departments' AS table_name,
       (SELECT COUNT(*) FROM test3.departments) AS original_count,
       (SELECT COUNT(*) FROM test3_restore.departments) AS restored_count
UNION ALL
SELECT 'projects',
       (SELECT COUNT(*) FROM test3.projects),
       (SELECT COUNT(*) FROM test3_restore.projects)
UNION ALL
SELECT 'workers',
       (SELECT COUNT(*) FROM test3.workers),
       (SELECT COUNT(*) FROM test3_restore.workers)
UNION ALL
SELECT 'tasks',
       (SELECT COUNT(*) FROM test3.tasks),
       (SELECT COUNT(*) FROM test3_restore.tasks)
UNION ALL
SELECT 'salaries',
       (SELECT COUNT(*) FROM test3.salaries),
       (SELECT COUNT(*) FROM test3_restore.salaries)
UNION ALL
SELECT 'tags',
       (SELECT COUNT(*) FROM test3.tags),
       (SELECT COUNT(*) FROM test3_restore.tags)
UNION ALL
SELECT 'tags_tasks',
       (SELECT COUNT(*) FROM test3.tags_tasks),
       (SELECT COUNT(*) FROM test3_restore.tags_tasks);
```

Сравните полученные значения.

Если резервная копия была создана из этой исходной базы и после её создания данные не изменялись, количество записей должно совпадать.

Обратите внимание: резервная копия отражает состояние базы на момент её создания. Если после этого в исходную базу добавлялись или из неё удалялись записи, результаты сравнения могут отличаться. Это не обязательно означает ошибку восстановления.

Выйдите из MySQL Client:

```sql
exit;
```

## 7. Настройка прав и проверка подключения пользователя user

В предыдущей лабораторной работе были созданы пользователи MySQL с различными правами доступа.

Пользователь `user` имеет права только на чтение исходной базы `test3`.

**Важно!** Права доступа, выданные на базу `test3`, автоматически не распространяются на новую базу `test3_restore`. Поэтому необходимо отдельно предоставить пользователю права на чтение восстановленной базы.

### 7.1. Проверка пользователя MySQL

Подключитесь к MySQL от имени администратора:

```bash
docker compose exec mysql mysql -uroot -p
```

Посмотрите, с каким значением `Host` создан пользователь `user`:

```sql
SELECT user, host
FROM mysql.user
WHERE user = 'user';
```

Запомните значение поля `Host`.

### 7.2. Выдача прав на чтение восстановленной базы

Если в предыдущем запросе для пользователя `user` указано значение Host `%`, выполните:

```sql
GRANT SELECT ON test3_restore.* TO 'user'@'%';
```

Если значение Host отличается от `%`, замените его в команде на фактическое значение из предыдущего запроса.

Например, если Host равен `localhost`:

```sql
GRANT SELECT ON test3_restore.* TO 'user'@'localhost';
```

Проверьте выданные права:

```sql
SHOW GRANTS FOR 'user'@'%';
```

Вместо `%` укажите фактическое значение Host пользователя, если оно отличается.

Выйдите из MySQL Client:

```sql
exit;
```

### 7.3. Проверка подключения пользователя user

Подключитесь к MySQL под пользователем `user`:

```bash
docker compose exec mysql mysql -uuser -p test3_restore
```

Введите пароль пользователя.

Выведите список таблиц:

```sql
SHOW TABLES;
```

Проверьте чтение данных:

```sql
SELECT *
FROM workers
LIMIT 5;
```

Если запросы выполняются успешно, значит пользователь имеет необходимые права на чтение данных.

### 7.4. Проверка запрета на изменение данных

Попробуйте выполнить изменение данных:

```sql
INSERT INTO workers (department_id, name)
VALUES (1, 'Test');
```

Ожидаемый результат — ошибка доступа, поскольку пользователь `user` имеет права только на чтение базы данных.

**Обратите внимание:** поля `department_id` и `name` используются потому, что именно такие поля присутствуют в таблице `workers`. Поле `department_id` обязательно для заполнения.

Выйдите из MySQL Client:

```sql
exit;
```
