# 🐧 Лабораторная работа № 8 --- Восстановление базы данных MySQL из резервной копии

## Цель работы

Научиться восстанавливать базу данных MySQL из ранее созданной резервной
копии.

Освоить работу со сжатыми SQL-дампами, проверку целостности архивов
GZIP, создание базы данных и импорт данных в MySQL 8.4, работающий в
Docker-контейнере.

Научиться проверять корректность восстановления структуры таблиц и
содержащихся в них данных.

## Необходимое программное обеспечение

-   Ubuntu Server 24.04 LTS (виртуальная машина).
-   Docker Engine.
-   Docker Compose Plugin.
-   Работающий Docker-контейнер `mysql84` с MySQL 8.4.
-   Текстовый редактор `nano`.
-   Резервная копия базы данных `test3`.

## 1. Исходные данные

В предыдущих лабораторных работах был развёрнут сервер MySQL 8.4 в
Docker-контейнере `mysql84` и подготовлена база данных `test3`.

Для выполнения данной работы необходимо восстановить базу `test3` из
ранее созданной резервной копии.

**Резервная копия уже размещена на Ubuntu Server** в каталоге:

``` text
/opt/mysql/backup/
```

Используемый файл:

``` text
test3_2026-11-24_02-00-00.sql.gz
```

Разберём название файла:

  Элемент        Назначение
  -------------- ------------------------------------
  `test3`        Имя базы данных
  `2026-11-24`   Дата создания резервной копии
  `02-00-00`     Время создания резервной копии
  `.sql`         SQL-дамп базы данных
  `.gz`          Сжатие файла с использованием GZIP

SQL-дамп содержит SQL-команды, необходимые для восстановления структуры
таблиц и данных.

В данной работе архив не требуется передавать с Windows или
распаковывать на отдельный компьютер.

## 2. Проверка резервной копии

Перед восстановлением необходимо убедиться, что файл присутствует на
сервере и не повреждён.

### 2.1. Проверка наличия файла

Перейдите в каталог резервных копий:

``` bash
cd /opt/mysql/backup
```

Посмотрите содержимое каталога:

``` bash
ls -lh
```

Убедитесь, что в списке присутствует файл:

``` text
test3_2026-11-24_02-00-00.sql.gz
```

Если для просмотра каталога требуются права администратора, используйте:

``` bash
sudo ls -lh /opt/mysql/backup/
```

### 2.2. Проверка формата файла

Выполните:

``` bash
file test3_2026-11-24_02-00-00.sql.gz
```

В результате должен отображаться тип файла, содержащий:

``` text
gzip compressed data
```

### 2.3. Проверка целостности архива

Выполните:

``` bash
gzip -t test3_2026-11-24_02-00-00.sql.gz
```

Если архив не повреждён, команда завершится без вывода сообщений об
ошибках.

Если у пользователя нет прав на чтение файла, выполните проверку с
правами администратора:

``` bash
sudo gzip -t /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz
```

### 2.4. Просмотр содержимого SQL-дампа

Посмотрим первые строки SQL-файла, не распаковывая архив на диск:

``` bash
gzip -dc test3_2026-11-24_02-00-00.sql.gz | head -n 30
```

Если для чтения файла требуются права администратора:

``` bash
sudo gzip -dc /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz | head -n 30
```

Убедитесь, что содержимое представляет собой SQL-команды.

**Важно!** Не удаляйте исходный архив и не изменяйте его содержимое. Он
понадобится для восстановления базы данных.

## 3. Подготовка сервера MySQL

В предыдущих лабораторных работах был развёрнут сервер MySQL 8.4 в
Docker-контейнере `mysql84`.

Повторная установка MySQL и создание контейнера не требуются.

### 3.1. Проверка состояния Docker

Перейдите в каталог проекта:

``` bash
cd /opt/mysql
```

Проверьте состояние контейнеров:

``` bash
docker compose ps
```

Убедитесь, что сервис `mysql` запущен, а контейнер `mysql84` имеет
статус `healthy`.

Если контейнер остановлен, запустите его:

``` bash
docker compose up -d
```

Повторно проверьте состояние:

``` bash
docker compose ps
```

### 3.2. Проверка наличия базы данных

Подключитесь к MySQL:

``` bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора MySQL.

Посмотрите список существующих баз данных:

``` sql
SHOW DATABASES;
```

Убедитесь, что база `test3` отсутствует.

**Важно!** Если база `test3` уже существует, не удаляйте её без
согласования с преподавателем. Восстановление поверх существующих таблиц
может привести к ошибкам импорта или изменению имеющихся данных.

Выйдите из MySQL Client:

``` sql
exit;
```

## 4. Создание пустой базы данных test3

Для восстановления SQL-дампа необходимо подготовить базу данных, в
которую будут импортированы таблицы и записи.

Подключитесь к MySQL:

``` bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора MySQL.

Создайте базу данных:

``` sql
CREATE DATABASE test3
CHARACTER SET utf8mb4;
```

Проверьте результат:

``` sql
SHOW DATABASES;
```

База `test3` должна появиться в списке.

Посмотрите её параметры:

``` sql
SHOW CREATE DATABASE test3;
```

Выйдите из MySQL Client:

``` sql
exit;
```

## 5. Восстановление базы данных из SQL-дампа

Теперь выполним импорт SQL-файла в созданную базу данных.

Перейдите в каталог проекта:

``` bash
cd /opt/mysql
```

Выполните команду:

``` bash
sudo gzip -dc /opt/mysql/backup/test3_2026-11-24_02-00-00.sql.gz \
| docker compose exec -T mysql sh -c \
'exec mysql -uroot -p"$(cat /run/secrets/mysql_root_password)" test3_restore'
```

Команда выполняет сразу несколько действий:

1.  `gzip -dc` читает сжатый архив и выводит его содержимое в несжатом
    виде.
2.  Символ `|` передаёт полученный SQL-текст следующей команде.
3.  `docker compose exec -T mysql` запускает команду внутри контейнера
    MySQL без выделения псевдотерминала.
4.  `mysql` подключается к серверу от имени пользователя `root`.
5.  Пароль администратора считывается из Docker Secret.
6.  Имя `test3` указывает базу данных, в которую импортируются
    SQL-команды.

Таким образом, архив распаковывается непосредственно в потоке передачи
данных и не требует создания дополнительного несжатого файла на диске.

**Важно!**

-   Исходный архив `test3_2026-11-24_02-00-00.sql.gz` остаётся
    нетронутым.
-   Для импорта используется пользователь MySQL `root`, поскольку
    восстановление может включать создание таблиц, индексов, триггеров и
    других объектов.
-   Команда рассчитана на SQL-дамп, который не содержит самостоятельного
    переключения на другую базу данных через `USE`.
-   Если импорт завершился с ошибкой, сохраните текст сообщения и
    сообщите преподавателю. Не повторяйте импорт поверх частично
    восстановленной базы без согласования.

При успешном выполнении MySQL обычно не выводит отдельное сообщение о
завершении импорта. Результат необходимо проверить следующими командами.

## 6. Проверка восстановления базы данных

После завершения импорта необходимо убедиться, что структура и данные
восстановлены корректно.

### 6.1. Проверка наличия таблиц

Подключитесь к MySQL:

``` bash
docker compose exec mysql mysql -uroot -p
```

Выберите базу данных:

``` sql
USE test3;
```

Выведите список таблиц:

``` sql
SHOW TABLES;
```

Убедитесь, что в базе присутствуют таблицы:

-   `departments`;
-   `projects`;
-   `workers`;
-   `tasks`;
-   `salaries`.

### 6.2. Проверка количества записей

Выполните запросы:

``` sql
SELECT COUNT(*) AS departments_count
FROM departments;

SELECT COUNT(*) AS projects_count
FROM projects;

SELECT COUNT(*) AS workers_count
FROM workers;

SELECT COUNT(*) AS tasks_count
FROM tasks;

SELECT COUNT(*) AS salaries_count
FROM salaries;
```

Запишите полученные результаты.

Количество записей позволяет проверить, что данные действительно были
импортированы, а не только созданы пустые таблицы.

### 6.3. Проверка содержимого таблиц

Посмотрите несколько записей из восстановленной таблицы сотрудников:

``` sql
SELECT *
FROM workers
LIMIT 10;
```

Посмотрите список отделов:

``` sql
SELECT *
FROM departments;
```

Проверьте связь сотрудников с отделами:

``` sql
SELECT
    w.id,
    w.first_name,
    w.last_name,
    d.name AS department
FROM workers AS w
JOIN departments AS d
    ON w.department_id = d.id
LIMIT 10;
```

Убедитесь, что запросы выполняются и возвращают данные.

### 6.4. Сравнение исходной и восстановленной баз

Теперь сравним количество сотрудников в исходной базе `test3` и восстановленной базе `test3_restore`.

Выполните:

```sql
SELECT COUNT(*) AS original_workers
FROM test3.workers;

SELECT COUNT(*) AS restored_workers
FROM test3_restore.workers;
```

Сравните полученные значения. Если резервная копия была создана из этой исходной базы и после её создания данные не изменялись, количество записей должно совпадать.

При необходимости аналогично сравните количество записей в остальных таблицах:

```sql
SELECT 'departments' AS table_name,
       (SELECT COUNT(*) FROM test3.departments) AS original_count,
       (SELECT COUNT(*) FROM test3_restore.departments) AS restored_count
UNION ALL
SELECT 'projects',
       (SELECT COUNT(*) FROM test3.projects),
       (SELECT COUNT(*) FROM test3_restore.projects)
UNION ALL
SELECT 'workers',
       (SELECT COUNT(*) FROM test3.workers),
       (SELECT COUNT(*) FROM test3_restore.workers)
UNION ALL
SELECT 'tasks',
       (SELECT COUNT(*) FROM test3.tasks),
       (SELECT COUNT(*) FROM test3_restore.tasks)
UNION ALL
SELECT 'salaries',
       (SELECT COUNT(*) FROM test3.salaries),
       (SELECT COUNT(*) FROM test3_restore.salaries);
```

Обратите внимание: резервная копия отражает состояние базы на момент её создания. Если после этого в исходную базу добавлялись или из неё удалялись записи, результаты сравнения могут отличаться. Это не обязательно означает ошибку восстановления.

Выйдите из MySQL Client:

``` sql
exit;
```

## 7. Проверка подключения пользователя user

В предыдущей лабораторной работе были созданы пользователи MySQL с
различными правами доступа.

Проверим, что пользователь `user` может подключаться к восстановленной
базе данных и читать её содержимое.

Подключитесь к MySQL под пользователем `user`:

``` bash
docker compose exec mysql mysql -uuser -p test3
```

Введите пароль пользователя.

Выведите список таблиц:

``` sql
SHOW TABLES;
```

Проверьте чтение данных:

``` sql
SELECT *
FROM workers
LIMIT 5;
```

Если запросы выполняются успешно, значит пользователь имеет необходимые
права на чтение данных.

Попробуйте выполнить изменение данных:

``` sql
INSERT INTO workers (first_name)
VALUES ('Test');
```

Ожидаемый результат --- ошибка доступа, поскольку пользователь `user`
имеет права только на чтение базы данных.

Выйдите из MySQL Client:

``` sql
exit;
```

-   Контейнер `mysql84` работает.
-   База данных `test3` создана.
-   SQL-дамп успешно импортирован.
