# 🐧 Лабораторная работа № 9 — Создание пользователей и управление правами доступа в MySQL

## Цель работы

Научиться создавать пользователей MySQL, назначать им привилегии и управлять доступом к базам данных.

Освоить механизмы разграничения прав доступа в MySQL 8.4, научиться проверять разрешённые и запрещённые операции под разными учётными записями.

## Необходимое программное обеспечение

- Ubuntu Server (виртуальная машина).
- Docker Engine.
- Docker Compose Plugin.
- Работающий Docker-контейнер `mysql84` с MySQL 8.4.
- Восстановленная база данных `test3` из лабораторной работы № 8.
- MySQL Workbench (при наличии) или консольный клиент MySQL.

## 1. Подготовка к работе

В предыдущей лабораторной работе была восстановлена база данных `test3` из резервной копии OpenPanel Server.

В данной работе необходимо создать двух пользователей MySQL с разными уровнями доступа:

| Пользователь | Назначение | Права |
|---|---|---|
| `user` | Обычный пользователь | Только чтение данных |
| `admin` | Администратор базы данных | Все права на базу `test3` |

Важно понимать, что пользователи создаются непосредственно в MySQL. Это не пользователи операционной системы Ubuntu и не пользователи Docker.

### 1.1. Проверка состояния контейнера

Перейдите в каталог проекта:

```bash
cd /opt/mysql
```

Проверьте состояние контейнера:

```bash
docker compose ps
```

Убедитесь, что контейнер `mysql84` запущен и имеет статус `healthy`.

### 1.2. Проверка наличия базы данных

Подключитесь к MySQL под пользователем `root`:

```bash
docker compose exec mysql mysql -uroot -p
```

Введите пароль администратора MySQL.

Выполните:

```sql
SHOW DATABASES;
```

Убедитесь, что в списке присутствует база данных `test3`.

Проверьте наличие таблиц:

```sql
USE test3;
SHOW TABLES;
```

Если таблицы присутствуют, можно переходить к следующему этапу.

## 2. Создание пользователей MySQL

Для управления пользователями и их привилегиями необходимо подключиться к MySQL под учётной записью `root`.

Если вы ещё не подключены, выполните:

```bash
docker compose exec mysql mysql -uroot -p
```

### 2.1. Создание пользователя user

Выполните SQL-запрос:

```sql
CREATE USER 'user'@'%' IDENTIFIED BY 'UserPassword123!';
```

Разберём команду:

| Элемент | Назначение |
|---|---|
| `CREATE USER` | Создание нового пользователя |
| `'user'` | Имя пользователя |
| `'%'` | Разрешение подключения с любого IP-адреса |
| `IDENTIFIED BY` | Установка пароля |

Таким образом, создан пользователь `user`, который пока не имеет специальных прав на базу данных `test3`.

### 2.2. Создание пользователя admin

Аналогичным образом создайте второго пользователя:

```sql
CREATE USER 'admin'@'%' IDENTIFIED BY 'AdminPassword123!';
```

Теперь в MySQL существуют две новые учётные записи:

- `user`;
- `admin`.

**Важно!** Значение `%` разрешает подключение с любых сетевых адресов, но само по себе не открывает доступ к MySQL извне. Подключение также должно быть разрешено настройками Docker, сети и межсетевого экрана.

В учебном стенде используйте собственные пароли, если преподаватель не предоставил готовые.

### 2.3. Проверка созданных пользователей

Выполните:

```sql
SELECT user, host
FROM mysql.user
WHERE user IN ('user', 'admin');
```

В результате должны отобразиться две созданные учётные записи.

## 3. Назначение прав пользователю user

Пользователю `user` необходимо предоставить возможность только просматривать данные базы `test3`.

Для этого используется привилегия `SELECT`.

Выполните:

```sql
GRANT SELECT ON test3.* TO 'user'@'%';
```

Разберём команду:

| Элемент | Назначение |
|---|---|
| `GRANT` | Назначение привилегий |
| `SELECT` | Право чтения данных |
| `test3.*` | Все таблицы базы данных `test3` |
| `'user'@'%'` | Пользователь, которому назначаются права |

Таким образом, пользователь `user` получает право выполнять запросы на чтение данных из всех таблиц базы `test3`.

При этом он не сможет добавлять, изменять или удалять записи.

### 3.1. Проверка назначенных прав

Выполните:

```sql
SHOW GRANTS FOR 'user'@'%';
```

В результате среди выведенных привилегий должна присутствовать строка:

```sql
GRANT SELECT ON `test3`.* TO `user`@`%`
```

## 4. Назначение прав пользователю admin

Теперь необходимо предоставить пользователю `admin` все привилегии на базу данных `test3`.

Выполните:

```sql
GRANT ALL PRIVILEGES ON test3.* TO 'admin'@'%';
```

Разберём команду:

| Элемент | Назначение |
|---|---|
| `GRANT` | Назначение привилегий |
| `ALL PRIVILEGES` | Все доступные привилегии в указанной области |
| `test3.*` | Все таблицы базы данных `test3` |
| `'admin'@'%'` | Пользователь, которому назначаются права |

Пользователь `admin` получает возможность:

- Просматривать данные.
- Добавлять записи.
- Изменять записи.
- Удалять записи.
- Создавать таблицы.
- Изменять структуру таблиц.
- Удалять таблицы.

**Важно!** Привилегии назначаются только на базу `test3`. Пользователь `admin` не получает глобальных прав администратора MySQL и не может автоматически управлять другими базами данных.

### 4.1. Проверка назначенных прав

Выполните:

```sql
SHOW GRANTS FOR 'admin'@'%';
```

Убедитесь, что среди привилегий присутствует:

```sql
GRANT ALL PRIVILEGES ON `test3`.* TO `admin`@`%`
```

## 5. Проверка прав доступа пользователя user

На этом этапе необходимо проверить, что назначенные привилегии действительно работают.

Выйдите из учётной записи `root`:

```sql
exit;
```

Подключитесь под пользователем `user`:

```bash
docker compose exec mysql mysql -uuser -p test3
```

Введите пароль пользователя `user`.

### 5.1. Проверка разрешённой операции SELECT

Выполните:

```sql
SELECT * FROM workers LIMIT 10;
```

Ожидаемый результат: запрос выполняется успешно, пользователь получает данные из таблицы `workers`.

### 5.2. Проверка запрещённой операции INSERT

Попробуйте добавить новую запись:

```sql
INSERT INTO workers (name)
VALUES ('Тестовый сотрудник');
```

Ожидаемый результат: MySQL возвращает ошибку недостаточных привилегий.

Например:

```text
ERROR 1142 (42000): INSERT command denied to user 'user'@'...'
```

Это означает, что пользователь не имеет права добавлять записи.

### 5.3. Проверка запрещённой операции UPDATE

Попробуйте изменить существующую запись:

```sql
UPDATE workers
SET name = 'Новое имя'
WHERE id = 1;
```

Ожидаемый результат: операция завершается ошибкой недостаточных привилегий.

### 5.4. Проверка запрещённой операции DELETE

Попробуйте удалить запись:

```sql
DELETE FROM workers
WHERE id = 1;
```

Ожидаемый результат: операция завершается ошибкой недостаточных привилегий.

Выйдите из MySQL Client:

```sql
exit;
```

**Вывод:** пользователь `user` может читать данные, но не может изменять содержимое базы данных.

## 6. Проверка прав доступа пользователя admin

Теперь проверим возможности пользователя `admin`.

Подключитесь к MySQL:

```bash
docker compose exec mysql mysql -uadmin -p test3
```

Введите пароль пользователя `admin`.

### 6.1. Проверка разрешённой операции SELECT

Выполните:

```sql
SELECT * FROM workers LIMIT 10;
```

Запрос должен выполниться успешно.

### 6.2. Проверка разрешённой операции INSERT

Добавьте тестовую запись:

```sql
INSERT INTO workers (name)
VALUES ('Тестовый сотрудник');
```

Операция должна выполниться успешно.

### 6.3. Проверка добавленной записи

Выполните:

```sql
SELECT * FROM workers
WHERE name = 'Тестовый сотрудник';
```

Убедитесь, что новая запись присутствует в таблице.

### 6.4. Проверка разрешённой операции UPDATE

Измените добавленную запись:

```sql
UPDATE workers
SET name = 'Изменённый сотрудник'
WHERE name = 'Тестовый сотрудник';
```

Проверьте результат:

```sql
SELECT * FROM workers
WHERE name = 'Изменённый сотрудник';
```

Имя записи должно измениться.

### 6.5. Проверка разрешённой операции DELETE

Удалите тестовую запись:

```sql
DELETE FROM workers
WHERE name = 'Изменённый сотрудник';
```

Проверьте результат:

```sql
SELECT * FROM workers
WHERE name = 'Изменённый сотрудник';
```

Запрос не должен вернуть удалённую запись.

Выйдите из MySQL Client:

```sql
exit;
```

**Вывод:** пользователь `admin` может выполнять операции чтения, добавления, изменения и удаления данных в базе `test3`.

## 7. Итоговая проверка разграничения доступа

Сравним возможности созданных пользователей.

| Операция | user | admin |
|---|:---:|:---:|
| `SELECT` — чтение данных | ✅ | ✅ |
| `INSERT` — добавление записей | ❌ | ✅ |
| `UPDATE` — изменение записей | ❌ | ✅ |
| `DELETE` — удаление записей | ❌ | ✅ |
| `CREATE TABLE` — создание таблиц | ❌ | ✅ |
| `ALTER TABLE` — изменение структуры | ❌ | ✅ |
| `DROP TABLE` — удаление таблиц | ❌ | ✅ |

Для дополнительной проверки можно снова подключиться под `root` и выполнить:

```sql
SHOW GRANTS FOR 'user'@'%';
SHOW GRANTS FOR 'admin'@'%';
```

Сравните выведенные привилегии.
